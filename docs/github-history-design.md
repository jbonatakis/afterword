# GitHub history in Afterword

**Proposed design · November 17, 2026**

Add the connected user's GitHub contributions to **All activity** as a read-only source. In the repositories the user selects, import issues and PRs they opened, comments they posted, and reviews they submitted. Return one result per issue or PR, with citations to the user's own contributions.

For example, “Why did I ask to keep the old webhook URL?” might surface the call where the migration was proposed and the user's review on a teammate's PR. If they wrote “Installed clients still send retries to the old URL,” the result shows that sentence, the PR title, the review date and a link to the comment.

## What goes into history

| What the user did | What Afterword saves |
| --- | --- |
| Opened an issue or PR | Its title, description, creation date and permalink. Keep its current state, including whether a PR eventually merged. |
| Commented on any issue or PR | The user's published comment or reply, its timestamp and permalink. For a teammate's item, keep the repository, number, type, title, author, current state and URL as context. |
| Reviewed a PR | Each submitted review, its verdict and date, and the user's published inline comments with file path, original line and permalink where available. An approval with no text still counts. |

Being assigned, mentioned or asked for a review does not qualify an item. Other people's descriptions, comments and reviews stay on GitHub, including replies on the user's own PR. **Open on GitHub** provides the full thread. Diffs, source files and CI output are outside the import. The saved text is the latest visible wording and marks edits.

The first release covers authorship, discussion and review. A teammate merging the user's PR updates its displayed state without creating personal activity. Standalone merges, close/reopen actions, and commits the user authored outside PRs are possible later additions that need their own discovery rules.

The sibling `../ghpr` checkout starts from “my PRs,” distinguishes complete and capped searches, and verifies an apparent disappearance before reporting a state change. Apply those ideas across open, closed and merged work. See `internal/gh/client.go`, `internal/gh/query.go` and the pagination discussion in its README.

## Connection and repository access

In **Settings → GitHub**, connect one GitHub.com account, choose repositories from its accessible installations, and choose the history depth. Start with the user's actions in the last 90 days and offer **All my available history** per repository. The cutoff applies to the action date. A review submitted yesterday qualifies even if the PR was opened last year. An old review stays searchable once imported.

Use a registered GitHub App with read access to metadata, issues and pull requests. The user authorizes Afterword through GitHub's device flow. A private organization may need an owner to install or approve the app for its repositories. Keep expiring user credentials and rotating refresh tokens in macOS Keychain. The desktop app can perform device-flow refresh using its public client ID. Only the native app contacts GitHub. [GitHub device authorization](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app#using-the-device-flow-to-generate-a-user-access-token) · [Token refresh](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens#refreshing-a-user-access-token-with-a-refresh-token)

Import and agent sharing are separate selections. Existing installations start with zero GitHub repositories shared through MCP. **Pause sync** retains searchable local history and shows the last successful check. **Remove repository** removes its local content, search entries, sync state and agent grant. **Disconnect and remove history** applies this to the account and clears its credentials. If a refresh establishes loss of access, immediately hide the affected scope from both readers, invalidate its grants and purge its records. If GitHub rejects the refresh credential, lock the account until the same GitHub user reauthorizes. Offline searches see the last verified snapshot and its timestamp. A Mac learns of remote revocation on its next access check.

## Import and reconciliation

Use a native sync coordinator and a private SQLite archive under `Application Support/Afterword/GitHub`. Store the connected user's stable GitHub ID, selected repository IDs, item headers, qualifying actions, FTS5 rows and sync progress. A header exists only while at least one retained action references it. Names, numbers and URLs can change.

1. **Discover personal activity.** Use separate repository-scoped GraphQL searches for issues the user opened, PRs they opened and PRs they reviewed, across all states. Use `author:@me` or `reviewed-by:@me` as appropriate. For conversation comments, page the viewer's own `issueComments` connection, requesting only IDs, dates and repository IDs until the repository and date checks pass. For reviewed PRs, fetch reviews filtered by the user's login and page their inline comments. Verify the actor ID before storing any action. Request only the identifying header for someone else's item. [GitHub search qualifiers](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests) · [User comments](https://docs.github.com/en/graphql/reference/users#user) · [PR reviews](https://docs.github.com/en/graphql/reference/pulls#pullrequest)
2. **Refresh.** Sync on connection, manual refresh and a proposed 15-minute interval while the app is running. Use overlapping discovery windows, deduplicate by GitHub ID, and checkpoint each stream only after its pages have been accounted for. Split capped searches into smaller time ranges and report unresolved windows as partial. Item update times help discover candidates. The user's creation, comment or review timestamp decides whether an action enters the selected period. [GitHub search limits](https://docs.github.com/en/rest/search/search#about-search)
3. **Reconcile.** Periodically replay personal discovery and recheck saved contributions to catch late indexing, edits and deletions. Confirm a missing contribution directly under verified repository access before pruning it and any orphaned header. Keep the previous snapshot through transient failures. Honor rate-limit reset and retry headers. [GitHub REST best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)

Show each repository's selected time range, last successful sync, queued items and whether backfill is complete, paused or waiting on GitHub. Keep this distinct from embedding coverage. A user searching last year's work should be able to tell whether Afterword has imported that period. An import finishing after repository removal must check the current selection before committing.

## Search and citations

Use a small shared activity result type in RecorderCore for calls, coding sessions and GitHub items. Keep storage and retrieval specific to each source. Today the native library groups calls and coding sessions into sections, while MCP interleaves the two ranked lists. Give **All activity** and `search_activity` one ordering rule. For a topic query, put exact qualified references first, then strong title or quoted-passage hits, then other ranked passages. Preserve each source's ranking within a tier and interleave ties deterministically. For browsing, sort by the latest activity in the requested interval. [Native library](../Sources/Afterword/RecordingLibraryView.swift) · [MCP activity search](../Sources/RecorderCore/AgentLibrary.swift)

- **Find an item.** Recognize a GitHub URL or `owner/repo#123` before ordinary tokenization. A bare `#123` needs repository context for an unambiguous match. Support repository, item type and action filters. “What did I review last week?” selects submitted reviews by their submission time, even on months-old PRs. The date of a teammate's reply or merge cannot move an item into that week.
- **Find evidence.** Index item titles, the user's contributions, review verdicts and cited file paths with the existing query parser and FTS5. Group matches by item and return the best personal contribution plus up to two additional citations. A title-only match identifies the item and labels how the user participated. Optional local embeddings cover the same saved content. [Coding archive](../Sources/RecorderCore/CodingArchive.swift) · [Semantic search](semantic-search.md)
- **Read in context.** Add a **GitHub** sidebar filter and a local timeline of the user's contributions. Show the action, timestamp, saved text, and an **Open on GitHub** link to the passage. Store edit and sync times separately. Render the saved Markdown locally.
- **Connect evidence.** A qualified PR reference in a call summary or coding message can link to the imported item when both sources are visible. Keep each source's citation. Shared branch names, nearby timestamps and similar display names provide search clues and are insufficient to assert a relationship.

Extend `search_activity` with `source: "github"` and return `kind: "github"`, item type, repository, title, stable item ID and cited passage IDs with permalinks. Add one read tool, `get_github_item`, with an optional passage anchor, pagination and `expected_revision`. Both tools read the local archive and enforce the current repository grants on each request, including direct ID lookups. Apply grants before ranking, counts, citations and cross-source links, and recheck before returning results. Include visible content, grant changes and actual search mode in pagination revisions. Keep the existing `get_changes` contract scoped to calls. [Agent access configuration](../Sources/RecorderCore/AgentAccess.swift) · [MCP contract](mcp.md#coding-activity)

## Delivery and verification

1. **Prove the import on one representative repository.** Verify installation and token renewal. Compare a known set of authored items, issue and PR comments, approvals without text, repeated reviews and inline-only replies against the archive. Check that a mention-only item produces no header and a teammate's unique reply text never appears in storage, keyword search, embeddings or MCP. Measure requests and time to the first searchable contribution before setting sync budgets.
2. **Ship local keyword search.** Deliver repository selection, resumable import, the timeline reader, All activity and scoped MCP in one usable slice. Exercise an interrupted page, same-timestamp updates, edited and deleted comments, a repository rename, and removal during an in-flight sync. Confirm a running MCP client loses access to a previously cited private item immediately after local revocation.
3. **Evaluate hybrid search and cross-source links.** Extend the frozen search-quality corpus with a call, coding session and reviewed PR about the same decision. Include a similarly titled distractor, duplicate issue numbers across repositories and a date-limited question about an old PR with a recent reply. Score the cited passage as well as the parent item, and verify current call and coding retrieval on the same benchmark. [Search quality benchmark](search-quality.md)
